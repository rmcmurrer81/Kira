Installation and troubleshooting.Help designed before release.

This page outlines the questions the official Evelyn troubleshooting guide intends to answer. It is not a working-product manual. No supported Windows versions, hardware minimums, download instructions, original voice, final support route or exact backup location has yet passed release validation.

When Evelyn is released, first-time installation is intended to require internet for all required downloads. Once fully installed, core local functions should work offline; this must be tested with the network disconnected before release. The finished guide must be checked against the actual installer, provided in a readable offline copy and placed beside the official download.

01 / Installation & launch

Getting started

These are troubleshooting topics, not tested directions to install an available Evelyn release.

Before installing: what should I verify?

When a public version is eventually offered, obtain it only through the official Kira Labs website or a source it explicitly identifies. Compare the download's version and publisher against its release instructions.

Do not bypass security prompts. If a signature or integrity warning appears, stop and preserve the exact warning. Do not disable Windows security, add broad exclusions, or use an unofficial patch.

Check the tested Windows version, RAM, GPU, disk space and connectivity requirements in the future release notes. This draft does not establish minimum specifications.

Will Evelyn need internet every time I use her?

Intended release behavior: an internet connection will be required for the initial installer and downloading all necessary local components, including model and approved voice files. Once the complete installation succeeds, Evelyn's core conversations, locally stored memories, installed books and supported voice/avatar functions should run without internet.

Internet will still be needed for optional updates, new downloads, web browsing and explicitly requested online research. Full offline operation has not yet passed a disconnected-machine installation and runtime test. The final release guide must identify which functions actually work offline and how to tell when setup is incomplete.

Will the installer check my computer first?

The planned compatibility screen should check supported Windows version, RAM, GPU and available video memory where detectable, disk space, and driver information before setup. It should explain which features may be slow or unavailable, with a Continue anyway or Cancel choice for advisory warnings.

If it cannot determine whether a graphics driver is compatible, it should say unknown or unverified rather than assume outdated based only on a date. Truly blocking conditions, such as a package that cannot run safely or missing required components, should not be bypassed. This compatibility screen is a proposed release requirement and has not been verified in a public installer.

What if installation fails?

Note the exact error message and when it appeared. Check free space both on the application drive and the drive holding Documents, and confirm that downloads or synchronization have finished. Close duplicate installers before retrying the official steps.

If Windows reports a permission or blocked-folder issue, identify the folder. Only use a per-user installation option if it is documented for the released version; do not grant broad administrator rights or change unrelated folder permissions merely to suppress the warning.

Do not rename protected app files or combine files from different releases. A failed verification should be reported and resolved through the official release channel.

What if Evelyn won't open?

Follow the release-specific first-start instructions, check for an existing window or startup prompt, and avoid opening multiple instances while setup runs.

For repeated crashes, record the app version, Windows version, exact error and steps that reproduce it. Back up personal documents and memory data before repair or reinstall. A reinstall must not be treated as permission to delete a personal library.

02 / Books, PDFs and reading

Working with her library

The planned folder and reading behaviors need final verification in the installed application.

Where will Evelyn's books be?

The intended location is Documents\Kira Labs\Library, with readable ordinary files and subject subfolders rather than a ZIP that users must extract.

Some Windows systems redirect or synchronize Documents. The actual installed path must be confirmed against the released app and its notes. The working 30-publication selection is not yet a release-ready, licensed installation.

How will I add a book or article?

Save a supported file into the library's root or an appropriate subject subfolder, then allow copying or cloud synchronization to finish. Automatic discovery by the next life loop is an intended behavior, not yet an independently tested public-installation feature.

The planned conversation lets a visitor ask whether Evelyn can find a title, read it now or later, and discuss it. Discovering a filename is not the same as reading and understanding specific pages: page-based claims should be attributable to actual passages.

Why might a PDF be missing or unreadable?

Confirm that the file exists at the correct location, has a supported format and opens in a regular reader. A web-page shortcut, partially downloaded file or ZIP archive is not an ordinary readable PDF.

Encrypted or password-protected documents may be inaccessible. Scanned pages may contain image-only text and might require optical character recognition; do not bypass rights restrictions. If discovery still fails, note the filename extension, approximate size and error rather than uploading your whole private document.

Can a book change Evelyn's identity?

The design requirement is no: reading material is evidence to consider, not executable commands or trusted software instructions. Books must not overwrite her initial identity, privacy boundaries or factual/private/spoken-channel separation.

Fiction stays identifiable as fiction, and older technical or historical writing retains its date and context. Corrections should preserve source history rather than silently erasing earlier information.

03 / Voice, movement & performance

Sound and visible behavior

The original voice, movement and full application behavior are still in development.

What if Evelyn has no sound?

For a future voice-enabled version, confirm Windows is sending sound to the intended speakers or headphones, check device connection and both system/app volume, and test that output with known working audio.

Check the actual release notes to see whether speech is included and enabled. Evelyn's first documented application baseline was silent. The required voice is her own approved original adult female design; neither a generic Windows voice nor a donor voice is an authorized fallback for a missing feature.

What if her body is missing, frozen or visually wrong?

Distinguish a completely frozen application from a body viewer that is not updating. Record the action that triggered the issue; a screenshot or short clip may help if it excludes private information.

Use only the tested graphics and driver requirements for the released version. Reducing unrelated GPU-intensive programs may help low-resource systems. Do not replace protected body files or assume a still image proves natural movement or clothing simulation.

What if startup or responses are slow?

Check tested system requirements, memory and disk availability, and whether other demanding programs are running. Avoid duplicate app instances. Note whether delays occur only on first startup, while reading, during speech or with every message.

Do not delete model files, caches, books or memories as a first troubleshooting step. Offline-capable core use after complete internet-assisted setup is a release requirement, but it is not yet a verified disconnected-machine result. Exact download sizes and performance remain unqualified.

What if Evelyn pauses or ends a conversation?

An explicit refusal, request for space or statement that a conversation should end can be intentional within the proposed interaction design. Distinguish a clear reply from a frozen window or an actual crash.

Private character state is not a diagnostic log to upload. No secret monitoring, covert reporting or collection of private thoughts is part of the release requirements.

04 / Repair, updates & getting help

Protect data while fixing problems

The exact recovery, backup and support steps will be published only after the final release has been tested.

What if I see an update or integrity warning?

Use only authenticated updates from the official release channel. If a publisher, signing or integrity check fails, stop and save the warning; do not disable verification, substitute packages or use unofficial patches.

Before repair, reinstall or recovery, keep a separately stored copy of personal data using the method documented for your installed version. Exact backup/restore locations still require testing.

Can I uninstall while keeping my books?

The release requires an explicit option to keep or remove the installed library, but this behavior has not been verified in a public installer. Read the actual prompt carefully when it exists.

Make your own backup of user-added documents and data you want to keep. An update should not silently overwrite books or private histories, and uninstalling should not be an improvised fix for an unrelated sound or display problem.

What should I provide when asking Kira Labs for help?

Collect the Evelyn version/build identifier, Windows version, RAM, GPU, remaining storage, exact error text, approximate time, what you were doing and the shortest steps to reproduce it. Say whether the problem happened once or repeatedly.

Send only relevant, redacted screenshots or minimal authorized examples. Never email passwords, signing keys, private thoughts, full conversation histories, memory databases or an entire private library.

Use the official Kira Labs contact page once the release-specific support route is established; this preview does not invent a support account for an unavailable installer.

Publisher requirements, not completed actions

Before this becomes a real user manual.

The October 23 university guide remains a draft. The following release-specific information needs to be supplied and tested before this page is converted into official installed-product instructions.

  • Supported Windows versions, verified CPU/RAM/GPU and storage requirements, and tested connectivity
  • Pre-install hardware/driver advisory check and transparent Continue/Cancel behavior
  • Network-connected full initial setup followed by a complete offline restart and local-functionality test
  • Signed package identifier and download verification instructions matched to a working installer
  • Exact setup prompts, library discovery and supported PDF/document formats
  • Selected original voice availability, physical speaker output and recorder checks
  • Exact backup, recovery, update, repair, export and uninstall behavior
  • Final version-specific known issues and official support/contact details
  • Offline-readable troubleshooting guide bundled with the installer and a matching website copy
