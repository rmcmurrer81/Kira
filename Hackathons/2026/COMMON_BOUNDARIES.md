# Common Build and Submission Boundaries

## Data

Use only synthetic, original, public-domain, or properly licensed demonstration data. Never place private Kira World data in a public hackathon repository.

Do not copy:

- real memories or conversation logs;
- Kira/Lisa/TemporaryAI private profiles;
- body meshes, anatomy assets, voice references, or generated private audio;
- email, calendar, tickets, hotel/flight details, OAuth credentials, API keys, or personal identifiers;
- copyrighted scripts, scenes, music, posters, screenshots, or branded characters.

## Claims

A prototype may demonstrate a workflow. It must not claim that:

- Kira has a finished body, physiology, medical function, or robotic embodiment;
- a health or accessibility tool diagnoses, treats, cures, or rehabilitates a condition;
- a phone call was made when only a simulation ran;
- sponsor services were integrated when only placeholders exist;
- synthetic test records are real users, customers, memories, or revenue.

## Human control

Any real-world action must be previewed and approved by the user. This includes phone calls, messages, bookings, purchases, calendar changes, and sharing sensitive information.

## Repository strategy

This incubator branch may hold planning and starter code. Before submission, create a dedicated repository for the selected project when the event requires a standalone public repository and license.

## AI assistance

Record the use of ChatGPT, Codex, or another coding assistant in the project build log whenever the rules permit it. If an event's rules are ambiguous, ask the organizer before generating substantive implementation code.
